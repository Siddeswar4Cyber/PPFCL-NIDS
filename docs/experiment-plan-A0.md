# A0 experiment protocol — planned, not run

2026-09-08. Methodology M0.2: this file extends [M0.1](CP0-methodology.md) with finite candidate sets, budget gates and the A0 privacy boundary. If these details conflict with the earlier provisional draft, M0.2 governs. User deadline: September 20, assumed 2026. All budgets below are design limits, not measured runtime predictions.

## Split and audit gate before model selection

EXP-001 audits all five existing dataset families read-only, recording file hashes, row/field counts, exact/trimmed header collisions, malformed rows, dtypes, missing/nonfinite values, labels, per-file distributions, constant/near-constant fields, cardinality, identifiers and timestamps. Use bounded chunks, no concatenation of multi-GB tables in RAM. Preserve positional IDs for duplicate column names; never trust a parser's silent renaming. Check duplicate payload rows and feature-identical conflicting labels with external-memory hashing/grouping; report any hash collision risk and verify candidate collisions before deletion. No automatic repair or deletion during audit.

EXP-002 commits dataset/split/feature manifests before fitting transforms. Audit can inspect quality and label support, but it is not an invitation to tune on test performance. Record that global quality inspection occurred. Prefer grouping duplicates together or an explicit deterministic deduplication rule before assignment. Never move difficult test examples after observing performance.

For CIC2017, compare a group-aware within-corpus development split with a predeclared held-out day/family stress test if support permits. A random-row test is insufficient as the only evidence. Day and attack type are confounded, so a held-out day is not a clean estimate of time alone. Missing host/time metadata restricts what leakage checks are possible.

For NF-UNSW, investigate chronological 60/20/20 development partitions using verified capture time and groups. Percentages are provisional: finalize actual cutoffs and label support after the audit, before training. Keep duplicate/overlapping flow groups on one side of a boundary; document resulting proportions. Check same-host/session dependence and capture discontinuities. Do not sort by an unverified epoch field and call the result temporal. A gap between windows is an optional registered sensitivity check, not a guarantee of independence.

The development population supports candidate selection. Freeze a separate public reference subset for privacy configuration and a disjoint curated population for privacy-confirmatory runs. Disjointness is at the declared record/group level, not merely a different random seed. A privacy statement is conditional on curation and public configuration, not a guarantee for the earlier data audit. The final test may be publicly evaluable benchmark data, but its performance remains sealed for scientific selection.

NF-CIC2018 is the proposed untouched external domain. Its schema/quality may be audited before training; no external performance feedback enters selection. ToN/BoT are optional additional external tests, not tuning substitutes. Map only verified common units/features. Binary benign/attack mapping is primary; do not conflate unrelated attack-family names. Any adapter fitted on external data constitutes adaptation and must be evaluated separately from zero-shot transfer.

## Resource and tuning policy

Start with an isolated Python environment after runtime discovery, pin actual installed versions, and benchmark CPU/GPU availability. Do not assume CUDA support from the GPU name. Allocate at most one training job at a time. Initial ceilings: 12 GB host working memory and 4 GB GPU allocation, leaving headroom for the OS; revise only from measured pilot evidence. Record peak process RAM and allocated/reserved GPU memory separately.

First pilot uses at most 100,000 training records from the permitted training region, sampled by a documented label-independent policy; validation must retain its natural prevalence. Record sample fractions and seed. Expand to 500,000 or full training data only if measured fit and I/O costs support it. Minority oversampling or weighting is an explicit training-only candidate; it is not used silently in the DP path because sampling/accounting may change.

Model pilot: at most four configurations per family, seed 17. LR regularization, tree depth/node budget and MLP width/learning rate are the principal axes. MLP initial widths (64,32), at most 10 epochs with selection-only validation; no batch normalization. Select one configuration per family before confirmation seeds 17, 29 and 43. If only one seed is feasible, report that limitation; do not manufacture confidence intervals. Tree/XGBoost trials must use recorded thread limits and estimator/round caps.

FL pilot: five clients, full participation, 20 rounds and one local epoch with a maximum local-step cap. Record actual examples/steps because equal epochs are unequal work on unequal client sizes. Fix initialization and client sampling sequence across methods. Compare one IID reference and two synthetic label-skew Dirichlet assignments (alpha 1.0 and 0.1) only when minimum client/class support is feasible. Record unsuccessful assignment attempts and the fallback rule. These assignments are sensitivity experiments, not measured institutions. A 60% participation or quantity-skew extension is conditional on budget. Normalize actual work when interpreting FedNova or partial participation.

Core FL tuning cap: three configurations per method (FedAvg local/server learning rate; FedProx proximal strength; FedAdam server rate with other optimizer settings fixed). Cap the whole FL pilot family at four hours of active compute; use partial logs to reduce the grid transparently if needed. A common round cap does not replace reporting compute and bytes. Confirmation runs may extend to 50 rounds only after cost extrapolation and a registered amendment.

Privacy pilot target epsilons 3 and 8 are exploratory comparison points, **not** a declaration of acceptable institutional privacy. Choose delta before runs, initially delta = 1/(10 × N_min), where N_min is a public, preregistered population-size bound for the study, not a newly released exact private count. Report this bound and its basis. Sampling probability, expected-batch normalization, noise and schedule must have a defensible behavior on adjacent datasets; ordinary data-loader defaults are not enough. Calibrate noise to the fixed maximum steps with the selected accountant; log realized epsilon and numerical settings. The comparison stops if either point cannot be implemented with a valid mechanism. Do not increase epsilon after observing a weak private test score. Clip norm starts at a public fixed trial value 1.0; any tuning is limited to public-reference data. Privacy-preserving confirmation cannot use non-private early stopping on the protected population. DP training and release accounting is reviewed before model metrics are interpreted.

CL pilot: three tasks with naturally supported periods; deterministic task boundaries fixed before fitting. ER reservoir capacity 1,000 examples per client is an initial cap, with actual bytes recorded. EWC and LwF receive at most three regularization-strength trials each. Fairness reports both equal optimizer-step budgets and the extra forward/gradient operations inherent in methods; it does not pretend identical epochs mean identical cost. Reusing a previous DP model as teacher needs a complete release-history check. ER/EWC may remain non-private comparators if no defensible private integration is implemented within the deadline.

Time allocation: September 8 research/A0; September 9 audit/environment/splits; September 10-11 baselines; September 12 FL; September 13 privacy; September 14 CL; September 15-16 interactions/generalization; September 17 freeze/final tests; September 18-19 report, reproducibility and viva; September 20 submission buffer. This is a work plan, not a scheduled automation or completion promise. If gates slip, remove optional candidates first, then publish a reduced, explicit scope. Never compensate by weakening leakage/privacy rules.

## Metrics, uncertainty and selection

Primary operational task: benign/attack classification. Report attack precision, recall and F1, binary macro-F1, PR-AUC with attack positive, benign FPR, and recall for each attack family. Complementary multiclass uses a fixed label universe, per-class support and macro-F1. State the zero-division policy; distinguish an absent class from a present class with zero recall. Do not compare binary macro-F1 directly with multiclass macro-F1 or mean client attack F1.

Report pooled, equal-client mean, worst eligible client and per-domain scores. Define eligibility from pre-training support; publish excluded-client counts rather than hiding low scores. Threshold selection uses validation only: report threshold 0.5 for probabilistic baselines plus one validation-selected operating point under a benign-FPR target fixed after the first baseline and before challenger selection. Publish the target even if unattainable. Anomaly models require a separate threshold calibration rule.

Let A[t,j] be the fixed-metric score on task j after learning task t, using the same evaluation records. Final average performance is mean_j A[T,j]. For old tasks j<T, forgetting is mean_j(max over k=j..T of A[k,j] − A[T,j]); BWT is mean_j(A[T,j] − A[j,j]). Exclude the newly learned task from old-task forgetting. FWT, if computed, compares A[j−1,j] with the registered untrained/reference score for task j. Define the task metric/support before training and keep it unchanged across t. Development task matrices guide CL selection; final-test matrices are computed only after configuration freeze, using archived checkpoints if needed.

Resource metrics: wall-clock training/validation separately, examples and steps, rounds, model/node counts, model bytes, local state/buffer bytes, measured serialized upload/download bytes, peak RAM/VRAM, inference batch size and p50/p95 timing after warmup. Python-loop or in-memory simulation communication is a byte estimate unless actual transport is measured. State hardware, power mode when available and framework versions. No extrapolation from prediction latency to complete-flow detection latency.

Use paired seeds/configurations and show all seed results, mean and standard deviation. Cluster/bootstrap uncertainty is optional only with defensible independent groups; row-wise bootstrapping correlated flows would overstate precision. Three seeds are a minimal sensitivity check, not strong population inference. No t-test from heterogeneous client scores treated as independent training replicates.

Selection rule: discard scientifically invalid runs; compare validation detection, worst-client/minority behavior and measured cost; retain the Pareto frontier. After EXP-003, preregister a practically meaningful score/cost margin for subsequent stages. Until then, no universal performance threshold exists. Prefer the simpler candidate when observed differences are smaller than seed variation and no secondary benefit is demonstrated. Report trade-offs when one method improves retention but harms adaptation/privacy utility.

## Finalization and failure policy

Before final evaluation, commit exact configs, source/environment versions, seeds, transforms, checkpoints, thresholds, task order, final/external manifest hashes and the decision log. Freeze which candidate and baselines will be evaluated. The registry must identify every planned, running, completed, failed or superseded run.

A crashed run is not a negative scientific score. Record the error, suspected cause, fix and rerun need. An invalid split/accountant invalidates affected claims and requires a new version. After final-test exposure, further development belongs to a clearly labeled follow-up study with a fresh holdout if available; never relabel the same exposed test as untouched.
